# Privacy and security

**Proceed to Create OKF** is an explicit user action that creates a new local bundle in a chosen parent folder and named subfolder. Initial creation writes generated source-derived Markdown directly; changes to an existing bundle remain subject to diff review. The output is registered as a document repository, its location is remembered locally, and `.okf-studio.json` records the source repository ID. This workflow has no model/network calls. Bundle files are ordinary user files and remain when the local index is cleared.

Saved views and navigation preferences are stored in local VS Code webview state. This includes view names, search queries, repository IDs, folder/path filters and selected record IDs. It excludes source bodies, questions, answers and provider credentials. It is separate from the derived catalog; use **Quality & Governance → Local data controls → Clear saved views & preferences** to remove it. Saved views never automatically trigger searches or model requests.

Default operation is local and offline. The extension stores selected repository source text, metadata, chunks, vectors, proposals, snapshots and audit records under VS Code's global extension storage, separated by a hash of workspace root URIs. This includes source content: protect your operating-system account and disk. Local databases are not independently encrypted; credentials are kept separately in VS Code SecretStorage.

No telemetry is sent. Structured logs omit content and redact common credential and email patterns. Audit events retain actions, timestamps, subject IDs and trace IDs. Retention defaults to 90 days for completed proposals, audit events and vector snapshots; source catalog data persists until a repository or the local index is removed. A recoverable SQLite backup is retained. Session egress grants expire when the extension host restarts or configuration changes and can be revoked in Settings.

Remote model/vector calls require explicit consent for their destination and operation, independent of Workspace Trust. Common secrets and email addresses are redacted, but pattern-based filtering cannot identify every sensitive fact. Review the selected scope and destination before consenting. Qdrant receives vectors and opaque chunk/record IDs, not source bodies. PostgreSQL receives vectors and IDs over certificate-verified TLS. Provider credentials must be entered through the configuration command, never repository settings. These providers have their own retention policies.

The extension uses Workspace Trust and permission checks, bounded schemas, file caps, binary rejection, ignored credential directories, symlink/path guards, HTTPS with redirect rejection and conservative private-address blocking (loopback Ollama is explicitly allowed). Ingestion never runs imported files, Python, computation executors or attesters. Git imports disable hooks; native VS Code Git actions follow the user’s configured workflow and may run its hooks. Git is invoked without a shell, with hooks and recursive submodules disabled for imports. No archives are extracted; zip-slip inputs have no extraction surface.

Webview scripts use a nonce CSP and cannot connect to the network. React renders source/model content as text, never raw HTML. Retrieved documents are delimited data, not tool instructions. This reduces prompt-injection exposure but does not prove model obedience; generated answers remain untrusted and require human review.

MCP runs a bundled stdio child process. It can access only an authenticated loopback bridge for the current extension session. Its bridge token is ephemeral, not an external-provider credential. Read tools return redacted, bounded local evidence. Proposal creation prompts the user; approval of a diff is a second distinct permission boundary. The local operating-system user remains a trusted boundary.

## Publisher transition in 0.4.1

The public publisher is ParakramJain. On first activation in each workspace, a validated legacy catalog can be copied from the old `okf-studio-local` global storage location when no current catalog exists. Old catalog and source/OKF files are not deleted. Credentials remain in the old extension's SecretStorage and must be re-entered for the new publisher; egress grants start fresh. Removing the new catalog does not erase preserved legacy catalog files. After verifying the migration, manage retained old-profile data according to your retention needs.

## 0.4.0 visible controls

Vector Studio stores non-secret settings in VS Code user configuration. Synthetic embedding probes contain no repository text; vector connection tests do not create/delete collections or tables. Agent Hub context exports contain bounded source-derived evidence and must be handled as private files. Diagnostics export redacts common patterns but can retain source paths/identifiers. MCP runtime checks exercise the local packaged process/bridge and do not establish an external client's identity. The Features/About pages expose verification limits; see docs/SECURITY.md.
